# 6. The apartment and the Blender pipeline

[← Material wiring](05-material-wiring.md) · Next: [Tuning and troubleshooting →](07-tuning-troubleshooting.md)

The demo apartment is generated by a Python script, not modelled by hand, so
it can be rebuilt, resized or rearranged by editing numbers.

## Regenerating it

```bash
# headless, writes Art/Apartment.fbx
blender --background --python Tools/Blender/build_apartment.py -- --export Art/Apartment.fbx
```

Or open Blender, go to *Scripting › Open › build_apartment.py*, and run it. That
builds the scene in the open file. `Art/Apartment.blend` is the result, saved
for reference.

## Layout

12 × 9 m, one storey, 2.8 m floor to ceiling. Top view in Blender
coordinates (+X east, +Y north, origin at the centre of the floor):

```
y= 4.5 +-------------------------------+---------------+
       |                               |               |
       |        LIVING ROOM            |    BEDROOM    |
       |                               |               |
y= 0.5 |                               +----D----+-----+
       |                               |         |     |
y=-1.0 |- - - - - - - - - - - - - - - -D  HALL   D BATH|
       |        KITCHEN / DINING       |         |     |
y=-4.5 +-------------------------------+---D-----+-----+
     x=-6                             x=1      x=3.5  x=6
```

| Constant | Value | |
|---|---|---|
| `WALL_H` | 2.8 m | floor to ceiling |
| `EXT_T` / `INT_T` | 0.25 / 0.12 m | exterior / interior wall thickness |
| `SLAB_T` | 0.15 m | floor and ceiling slabs |
| `DOOR_H` | 2.1 m | doors are 0.9 m wide |
| `WIN_SILL` / `WIN_HEAD` | 0.9 / 2.2 m | windows |

Every wall has **real thickness**. A cutaway of paper-thin walls shows
nothing interesting at the cut. With thick walls you see the section.

## How it's built

`MeshBuilder` wraps a `bmesh` with per-face material slots and two
primitives, `box()` and `cylinder()`. Walls go through `wall(mb, a, b, t,
material, openings)`, which splits a wall into solid boxes around its door
and window openings (`door(s0, w)`, `window(s0, w)` give each opening's start and width along the wall).

The script produces four objects, which become four static meshes:

| Object → Static mesh | Material slots | Cuttable |
|---|---|---|
| `SM_Apartment_Walls` | `M_WallExterior`, `M_WallInterior` | yes |
| `SM_Apartment_Ceiling` | `M_Ceiling` | yes |
| `SM_Apartment_Floor` | `M_FloorWood`, `M_FloorTile` | no |
| `SM_Apartment_Furniture` | `M_Rug`, `M_Fabric`, `M_Wood`, `M_Counter`, `M_Metal`, `M_Bedding`, `M_Ceramic` | no |

Splitting by role, not by room, keeps the draw-call count tiny. It also makes
"which parts can be cut" a per-mesh/per-slot decision in Unreal.

The `MATERIALS` table at the top of the script holds each slot's base colour
and roughness. In Unreal those values are copied onto the matching `MI_*`
instance (Blender's Principled *Base Color* is linear, as are UE vector
parameters, so they transfer one to one).

## Coordinates and units

- **Units.** Blender metres → FBX (unit scale 1, `FBX_SCALE_NONE`) → Unreal
  imports at 100 uu per metre. The apartment arrives at its real size.
- **Axes.** The export uses Blender's defaults (−Z forward, Y up). Unreal is
  left-handed, so **Blender +Y becomes Unreal −Y**. The living room (Blender
  north-west) sits at Unreal `x < 0, y < 0`, which is where the demo cube is.
- **Pivot.** Every mesh's origin is the centre of the apartment at floor
  level, so all four go in at (0, 0, 0).

## Importing into Unreal

The demo content was imported headless with the ImportAssets commandlet
(Interchange FBX pipeline):

```bash
UE="/Users/Shared/Epic Games/UE_5.8/Engine/Binaries/Mac/UnrealEditor.app/Contents/MacOS/UnrealEditor"
"$UE" "$PWD/MyProject.uproject" -run=ImportAssets \
  -source="$PWD/Plugins/XRayCube/Art/Apartment.fbx" -dest="/XRayCube/Apartment" \
  -replaceexisting -nosourcecontrol -unattended -nopause -nosplash
```

Dragging the FBX into the Content Browser (with the editor open) does the
same. The importer creates a placeholder material per slot. Replace them with
the `MI_*` instances (*Static Mesh editor › Material Slots*) and delete them.

> After re-importing over the existing meshes, check the material slots: the
> importer may assign freshly created placeholder materials again. The slot
> names come from the Blender material names, so as long as those don't
> change, reassigning is a one-click job per slot.

## Editing the apartment

1. Change the constants or the room code in `build_apartment.py`.
2. Re-run it with `--export Art/Apartment.fbx`.
3. Re-import (above).
4. New material names? Add them to `MATERIALS`, create a matching `MI_*`
   instance of `M_XRayCutaway`, and assign it.
